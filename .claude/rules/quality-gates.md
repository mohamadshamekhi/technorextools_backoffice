# Quality gates: باگ، اصلاح خودکار، Definition of Done

Load when: کد را لمس می‌کنی (هر اندازه)، یا کاربر می‌پرسد «تمام شد؟».

## باگ یعنی چه (در این پروژه)

- خطای type زیر `strict` (بدون `any`/`!`/`@ts-ignore` برای خاموش‌کردنش).
- خطای runtime قابل پیش‌بینی: دسترسی به `undefined`/`null` مدیریت‌نشده، `catch` خالی یا خطای بلعیده‌شده.
- race condition در state کلاینتی — مثل امکان دو بار submit هم‌زمان بدون قفل `useTransition`/`pending`.
- ناسازگاری قرارداد API: تایپ در `src/lib/api/backoffice/<domain>.ts` با شکل واقعی در `docs/api/<section>.md` فرق دارد، یا `ApiError` مدیریت نشده.

توجه — این پروژه **Zod ندارد**. اعتبارسنجی از طریق بک‌اند + الگوی `ActionResult`/`fail`/`invalid` در `src/lib/forms.ts` انجام می‌شود، نه schema. پیشنهاد افزودن Zod یا هر پکیج جدید فقط با تأیید کاربر (`coding-standards.md`: «dependency set عمداً minimal است»).

## اصلاح خودکار، بدون درخواست جدا

هر بار فایلی را لمس می‌کنی، در همان فایل و فایل‌های مستقیماً مرتبط (import‌کننده/import‌شونده‌ی بلافصل)، اگر باگی از نوع بالا دیدی همان‌جا اصلاحش کن. در پاسخ یک‌خط بگو چه چیزی و چرا (`file:line`) — بدون این بخش را حذف نکن، ولی طولانی‌ترش هم نکن.

## گیت ورودی سرور اکشن‌ها (این ریپو route handler ندارد)

نقطه‌ی ورود داده‌ی کاربر «سرور اکشن» است (`app/(dashboard)/<x>/actions.ts`). کاری که این‌ها را لمس می‌کند ناتمام است مگر:

- ورودی تایپ صریح دارد (نه `any`).
- بدنه در `try/catch` است و خطا با `fail(error, "...")` به `ActionResult` فارسی تبدیل می‌شود — نه throw خام تا کاربر.
- اعتبارسنجی پیش از تماس با بک‌اند (مثل regex موبایل) از `invalid()` در `forms.ts` استفاده می‌کند.

## گیت دیزاین/UX (مطابق stack واقعی — Tailwind-only، بدون `cn()`/CSS Modules)

این پروژه صراحتاً از `cn()`/`clsx` یا CSS Modules استفاده نمی‌کند (`coding-standards.md`). هر کامپوننتی که لمس می‌کنی و یکی از این‌ها را دارد، همان‌جا اصلاح کن — مگر تغییر بصری بزرگ/سلیقه‌ای باشد، که فقط گزارشش کن و منتظر تأیید بمان:

- رنگ hex/rgb هاردکد به‌جای توکن تم.
- کلاس شرطی با تمپلیت لیترال طولانی و نامفهوم → استخراج به یک متغیر محلی خوانا (بدون افزودن پکیج).
- کامپوننتی که فقط چیدمان دسکتاپ دارد و در `< lg` نشکسته.
- عنصر تعاملی بدون `<button>`/`<a>` واقعی، یا بدون `label`/`aria-label`.
- `<img>` بدون `alt`، یا بدون کامنت eslint-disable مطابق الگوی `image-uploader.tsx` (این پروژه عمداً `next/image` استفاده نمی‌کند چون دامنه‌ی تصاویر آپلودی در `next.config.ts` remote pattern ندارد — این را بدون هماهنگی عوض نکن).

## SEO

پنل ادمین داخلی است، نه سایت عمومی. جز `/login` (که خودش فرم است، نه محتوای ایندکس‌پذیر) هیچ route عمومی‌ای وجود ندارد؛ الزام `buildMetadata`/JSON-LD در این ریپو موضوعیت ندارد. اگر تسکی واقعاً صفحه‌ی public/ایندکس‌پذیر اضافه کرد، همان‌جا سطح متادیتای لازم را از کاربر بپرس.

## Definition of Done

اجرا **یک‌بار، در پایان تسک/PR** — نه بعد از هر ادیت (طبق `token-economy.md`):

- [ ] typecheck تمیز (کامپایلر/ادیتور کافی است؛ فقط در شک از خطای type، `npx tsc --noEmit`).
- [ ] `npm run lint` بدون خطا/warning جدید.
- [ ] `npm run build` موفق — فقط وقتی کاربر تحویل واقعی/PR خواسته، طبق همان قانون.
- [ ] بقیه‌ی چک‌لیست در `workflow.md` (رشته‌های فارسی، RTL، موبایل+دسکتاپ، `loading.tsx`/`error.tsx`، بدون `console.log`).
- [ ] اگر تغییر ساختاری بود: یک خط در `cloud.md` ثبت شده.
